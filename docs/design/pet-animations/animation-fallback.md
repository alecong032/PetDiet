# 动画降级方案（T2.8.3）

> PetDiet · Android / Jetpack Compose / Material 3
> 依据：`animation-spec.md`（T2.7）、PRD §6.1（喂食动画 ≥30fps）、navigation-scheme.md §七（转场基线）、TDD §7.2（弱网/离线策略）、D-007（仅 Android）

## 一、目标与触发条件

在低端设备或系统限制下，用 Compose 原生动效或静态帧替代 Lottie，保证**动画不导致掉帧、不阻塞主流程**，同时保留状态可辨识性（用户仍能看出宠物处于哪种状态）。

### 1.1 触发条件（满足任一即降级）

| 类型 | 条件 | 判定方式 |
|---|---|---|
| 设备档位 | 运行内存 < 2GB，或 Android API 26–27（`Build.VERSION.SDK_INT`） | 启动时读取 `ActivityManager.MemoryInfo` + `Build.VERSION` |
| 运行时性能 | Lottie 首次播放掉帧率 > 20%（连续 3 次采样），或单帧渲染 > 50ms | 播放期采样 `Choreographer` 帧时间 |
| 系统设置 | 用户开启「减少动效」 | `ValueAnimator.areAnimatorsEnabled()`（API 26+ 推荐）；辅以 `Settings.Global.ANIMATOR_DURATION_SCALE = 0` |
| 电量/温控 | 系统省电模式激活（`PowerManager.isPowerSaveMode`） | 运行时监听 |
| 资源缺失 | Lottie 资源加载失败（解压/解析异常） | try-catch 回退 |

> 降级一旦触发，本次会话内**不回升高动效层级**（避免反复切换造成闪烁），但允许按 §2.1 继续下探（L1 → L2）；用户手动在设置页关闭降级（如提供）可即时恢复。

## 二、三档降级层级

| 层级 | 名称 | 表现 | 实现 | 适用 |
|---|---|---|---|---|
| L0 | 完整动效 | Lottie 矢量动画（6 状态循环 + 喂食 1.8s） | `LottieAnimation`（Compose） | 中高端设备、正常模式 |
| L1 | 关键帧交替 | 跨帧淡入淡出 200ms；每帧保持时长 = `animation-spec.md` §1.2 周期的一半（如 NORMAL 3.0s → 各帧 1.5s） | `AnimatedContent` + `Crossfade`，静态帧按 96dp 展示尺寸解码 | 低端设备、省电模式、Lottie 加载失败 |
| L2 | 静态呈现 | 单张 `frame-1` 静态图，状态切换用 200ms 淡入 | `AsyncImage` / `Image` | 极低端设备、减少动效开启、降级后仍掉帧 |

### 2.1 层级映射（按触发原因）

| 触发原因 | 起始层级 |
|---|---|
| 设备档位低（<2GB / API 26–27） | L1 |
| 运行时掉帧 | L1（若 L1 仍掉帧 → L2） |
| 减少动效开启 | L2（状态切换仍保留 200ms 淡入，符合无障碍最小动效）；**喂食路径例外**：沿用 0.5s 静态 EATING 帧（见 §2.2，与 animation-spec §2.3 一致） |
| 省电模式 | L1 |
| Lottie 资源加载失败 | L1（不因资源缺失阻断流程） |

### 2.2 喂食动画的降级

| 层级 | 喂食（`flow/feeding`）表现 |
|---|---|
| L0 | 完整 1.8s 时间轴（`animation-spec.md` §2） |
| L1 | 静态 EATING 帧 + 0.5s 淡入 →（写盘完成后）进入反馈屏 |
| L2 | 静态 EATING 帧 + 0.5s 淡入（与 L1 同）→ 写盘完成后进入反馈屏；反馈屏状态图作 200ms 淡入。**喂食路径在 L2 也保留这 0.5s 静态帧**，与 animation-spec §2.3「减少动效时播放 0.5s 静态 EATING 帧」一致 |

> 三档均**不改变**流程与数据行为：状态仍为 `EATING`、写盘与引擎计算时机不变、写盘期间仍禁用返回（`animation-spec.md` §2.3）。

### 2.3 转场的降级

| 层级 | 二级流程 push/pop | Tab 切换 | 弹层 |
|---|---|---|---|
| L0 | 300ms M3 forward/backward | 300ms M3 fade-through | 遮罩 150ms + 弹层 200ms |
| L1 | 200ms 淡入淡出（无位移） | 120ms 交叉淡入 | 遮罩 100ms + 弹层淡入 150ms |
| L2 | ≤100ms 淡入淡出或直接切换 | 直接切换 | 遮罩 + 弹层直接出现 |

**转场内的视觉效果**：L1 / L2 禁用 elevation / shadow 与模糊类效果（低端机上这些开销最大），层级改由 1dp 描边表达（与 animation-spec §3.3 的委托、T2.5.3 §四 的描边口径一致）。

## 三、实现约束

| 项 | 规则 |
|---|---|
| 帧率 | 各层级均须 ≥ 30fps（PRD §6.1）；L1 的两帧交替不得引入额外解码开销（帧预解码缓存） |
| 内存 | 静态帧按展示尺寸解码（统一 96dp），禁止全尺寸（1254×1254 px）直接解码 |
| 体积 | Lottie 资源每个 < 50KB（T2.8.1/2.8.2 验收）；降级路径不加载 Lottie 资源，节省运行时内存与解码开销（APK 体积不因此减小，资源仍随包分发） |
| 启动影响 | 降级判定为轻量同步调用，不进入冷启动关键路径，不影响 PRD §6.1 冷启动 <3s |
| 状态可辨识 | 各层级都须能区分 6 状态：L1/L2 依赖关键帧姿态差异；若某状态两帧姿态差异不足，须改用状态标签文字辅助（主页已有状态标签，见 `hifi/home.html`） |
| 生命周期 | 页面不可见（`ON_STOP`）时暂停动画播放，避免后台耗电 |
| 可观测 | 降级触发原因写入本地日志（便于 P7 测试期回收数据，不采集个人内容） |

## 四、与无障碍的关系

- 「减少动效」是**用户显式偏好**，优先级最高：无论设备档位，均直接进入 L2，且转场 ≤100ms。
- 降级不得移除状态信息：状态标签（文字 + 图标）与属性数值在任何层级都保持可用（`color-system.html` 色盲友好规则）。
- 降级不改变交互：按钮触控区、返回栈、预测性返回行为完全一致；降级层级与状态在配置变更（旋转）与进程重建后保持一致（不重启 Lottie、静态帧不闪回），与 navigation-scheme §七「旋转与进程恢复」对齐。
