02　置信度分级 · 三分支

识别结果按置信度路由，低置信度不直接进入记录（TDD §2.2 / §3.2）

> 0.90 · 自动确认

直接入记录并喂食

  • 无确认弹窗，一步完成
  • 记录标注「自动识别」
  • 仍可进入详情调整
0.70 – 0.90（含 0.90）· 候选选择

Top-3 候选列表确认

  • 展示候选 + 置信度 + 热量
  • 用户点选正确项
  • 选错可「重新识别」
< 0.70 · 手动输入兜底

搜索或手填

  • 提示识别不确定
  • 食物搜索 / 手动表单
  • 菜名 + 热量 + 营养素

03　异常流程与降级兜底

所有异常路径均不丢数据、不产生错误记录

AI 失败 / 超时

重试 1 次 → 提示用户 → 手动输入

  • 3s 超时，自动重试 1 次（TDD §4.3）
  • 仍失败 → 提示用户
  • 限流：指数退避 1s / 2s / 4s
  • ⇢ 手动输入兜底
弱网 / 离线

本地暂存，联网同步

  • 图片与记录暂存本地
  • 恢复后自动补识别 / 同步
  • 离线可查看历史（TDD §7.2）
无候选 / 识别为空

引导手动输入或重拍

  • 提示重新拍摄（光线/角度）
  • 或直接手动输入
  • 不自动写入错误记录
中途取消 / 重拍

丢弃本次操作

  • 不产生食物记录
  • 不触发喂食 / 状态变更
  • ↩ 返回首页

04　宠物反馈联动（喂食后）

摄入量对照每日卡路里目标，驱动宠物状态（PRD §2.3 + D-009）

条件（摄入 vs 每日目标）宠物状态反馈表现属性影响
摄入 < 60%（ratio < 0.60）HUNGRY（health < 30 则 SICK）😢 饥饿饱食度 ↓（intake_health −2）
摄入 60%–90%（0.60–0.90）NORMAL日常无增减
摄入 90%–110%（0.90–1.10）HAPPY / NORMAL😊 满足健康值 ↑（+3）
摄入 ≥ 110%（ratio ≥ 1.10）OVERFULL（含过饱+吃撑）🤢 过饱 / 吃撑健康值 ↓（>1.10 −1，>1.20 −4）
营养均衡HAPPY❤️ 健康健康值 ↑（PRD §2.3 简写口径）

状态映射优先级（satiety-map §4 / TDD §6.2.3）：① health < 30 → sick ② hunger ≥ 90 → overfull（含过饱+吃撑）③ hunger < 30 或 mood < 35 → hungry ④ mood ≥ 70 → happy ⑤ 其余 → normal。eating 由喂食动作触发，不参与映射。详见 docs/design/pet-nutrition/satiety-map.md。
