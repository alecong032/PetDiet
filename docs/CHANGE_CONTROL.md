## 二、变更控制流程

### 触发条件
以下情况必须走变更控制：
1. 需求变更（增删改功能、范围调整）
2. 技术方案变更（架构/数据模型/API/依赖重大调整）
3. 数值参数变更（TDD §6.2.4 参数表、卡路里公式）
4. 已冻结决策的撤销或修改（D-001~D-010）
5. 设计资源/设计规范变更（design-system.html、宠物形象/动画、P2 设计期产出，如颜色/字体/间距规范）

### 流程（5 步）

```
1. 提出变更 (CR)
   └─ 任何人/Agent 提出 Change Request，填写 CR 编号 + 描述 + 理由
2. 影响评估
   └─ 评估影响范围（PRD/TDD/LEDGER/代码/工作量/依赖）
3. 用户批准
   └─ 由用户（丛诗鸿）拍板：批准 / 驳回 / 暂缓
   └─ 批准后记录到 DECISIONS.md（D-0xx）
4. 更新文档
   └─ 同步更新 PRD.md / TDD.md / LEDGER.md / 相关文档
5. 落地实施
   └─ 更新基线（v1.0 → v1.1...）并记录变更历史
```

### 原则
- 未批准不实施；实施前先更新文档
- TDD 是标准，变更只改文档和代码，不反向迁就产出（D-002）
- Agent 不得自行批准 CR，必须用户拍板
