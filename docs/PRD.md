## 1. 产品概述

### 1.1 产品愿景

PetDiet 是一款**以虚拟宠物为载体的 AI 饮食追踪应用**。通过「拍照 → AI 识别 → 喂食宠物」的趣味闭环，让健康饮食管理变得轻松有趣。

### 1.2 核心价值主张

> **"吃得对，宠物才能陪你到老"**

传统饮食追踪 App（如 MyFitnessPal）枯燥乏味，用户留存率低。PetDiet 通过**情感化设计**（虚拟宠物），将每日饮食记录变成一件有温度的事：

- 📸 **一键拍照** — AI 自动识别食物，免去手动搜索
- 🍖 **趣味喂食** — 识别到的食物变成宠物的"食物"
- ❤️ **情感连接** — 宠物的健康状态直观反映用户的饮食习惯
- 📊 **潜在激励** — 通过照顾宠物来激励自己养成健康饮食的习惯

### 1.3 目标用户

| 维度 | 描述 |
|------|------|
| **年龄** | 全年龄段（18-35 为核心用户群） |
| **性别** | 不限（女性略多，约 6:4） |
| **使用场景** | 日常三餐拍照记录，饭后 5 分钟内完成 |
| **用户画像** | 关注健康但坚持不下来的"间歇性减肥者"、喜欢宠物的年轻用户、对 AI 技术有好感的尝新用户 |

### 1.4 首发市场

- **语言**: 简体中文
- **地区**: 中国大陆
- **平台**: iOS 16+ / Android 8+

### 2.4 卡路里目标计算

基于 Mifflin-St Jeor 公式：

```
BMR (基础代谢率):
  男性: 10×体重(kg) + 6.25×身高(cm) - 5×年龄 + 5
  女性: 10×体重(kg) + 6.25×身高(cm) - 5×年龄 - 161

TDEE (每日总消耗) = BMR × 活动系数:
  久坐:    1.2
  轻度:    1.375  (每周 1-3 次运动)
  中度:    1.55   (每周 3-5 次运动)
  高度:    1.725  (每周 6-7 次运动)
  极高:    1.9    (每天高强度运动)

每日卡路里目标:
  减重:  TDEE - 500 kcal  (约每周减 0.5kg)
  维持:  TDEE
  增重:  TDEE + 300 kcal
```

## 3. 宠物系统设计 (MVP 版)

### 3.1 宠物属性模型

| 属性 | 图标 | 范围 | 说明 | 初始值 |
|------|------|------|------|--------|
| **饱食度** | 🍖 | 0-100 | 反映今日摄入vs目标，与卡路里目标联动 | 50 |
| **健康值** | ❤️ | 0-100 | 综合健康指标，受饮食均衡度+摄入量影响 | 100 |
| **心情值** | 😊 | 0-100 | 由饱食度和健康值决定的衍生值 | 80 |

> 💡 **核心创新**: 饱食度不再仅依赖"单次喂食量"，而是与**每日卡路里目标**联动：
> - 摄入 ≈ 目标 → 饱食度 70-90（满足）
> - 摄入 > 目标 120% → 饱食度 >95（吃撑，健康值↓）
> - 摄入 < 目标 60% → 饱食度 <30（饥饿）

### 3.2 属性计算规则

#### 饱食度（与卡路里目标联动）

```
今日摄入比例 = 今日累计摄入热量 / 每日卡路里目标

饱食度映射:
  摄入比例 < 60%  → 饱食度 = 摄入比例 × 50    (饥饿区间, 0-30)
  摄入比例 60-90% → 饱食度 = 30 + (比例-0.6)×133 (正常区间, 30-70)
  摄入比例 90-110%→ 饱食度 = 70 + (比例-0.9)×200 (满足区间, 70-90) ← 理想
  摄入比例 110-120%→饱食度 = 90 + (比例-1.1)×100 (过饱区间, 90-100)
  摄入比例 > 120% → 饱食度 = 100                (吃撑, 健康值惩罚)
```

#### 健康值变化（多重因素）

```
每次喂食时评估:

1. 摄入量评估 (与卡路里目标对比):
   - 摄入比例 90-110% (合理):     健康值 +3   ← 最佳
   - 摄入比例 110-120% (略多):    健康值 -1
   - 摄入比例 > 120% (吃撑):      健康值 -4   ← 惩罚
   - 摄入比例 < 60% (节食):       健康值 -2

2. 营养均衡评估:
   - 均衡 (蛋白质≥15% 且 脂肪≤35%): 健康值 +2
   - 不均衡 (高脂>40% 或 高糖):     健康值 -3
   - 普通:                           健康值 ±0

3. 时间衰减 (App 回前台时计算):
   - 饱食度 < 20 持续 6 小时: 健康值 -5
   - 饱食度 > 95 持续 4 小时: 健康值 -3 (长期过饱)

健康值 = clamp(当前健康值 + 摄入评估 + 营养评估, 0, 100)
```

#### 心情值（衍生值）

```
心情值 = f(饱食度, 健康值, 摄入比例)
  - 饱食度 70-90 AND 健康值 > 60:                心情值 = 90 (开心) ← 理想状态
  - 饱食度 > 90 (吃撑) OR 健康值 < 30:           心情值 = 25 (难受)
  - 饱食度 < 30 (饥饿):                          心情值 = 20 (难过)
  - 其他:                                         心情值 = 50 (正常)
```

### 3.3 宠物状态 → 视觉映射 (MVP)

| 状态 | 表情 | 触发条件 | 颜色 | 动画 | 反馈文案 |
|------|------|---------|------|------|---------|

## 4. AI 食物识别方案

### 4.1 当前方案: 第三方 AI API

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **首选: 第三方食物识别 API** | 调用成熟的云端 AI 服务 | 准确率高、无需训练、快速上线 | 需要网络、API 成本、数据外流 |
| **备选: 自建模型（后续）** | 训练轻量化模型部署到端侧 | 离线可用、隐私友好、无 API 成本 | 需训练数据、初期准确率低 |

### 4.2 识别流程

```
用户拍照/选图
      │
      ▼
  图片预处理 (压缩/裁剪)
      │
      ▼
  调用 AI API
      │
      ▼
  ┌─────────────────────┐
  │ 返回 Top-K 结果      │
  │ [{name, confidence,  │
  │   calories, ...}]    │
  └────────┬────────────┘
           │
           ▼
  ┌─────────────────────────────────┐
  │ 置信度分级处理                    │
  │                                  │
  │ >90%: 自动确认，直接喂食          │
  │ 70-90%: 展示 Top-3 供用户选择     │
  │ <70%: 提示"识别不确定"，建议手动输入│
  └────────┬────────────────────────┘
```

### 4.3 AI 兜底策略

| 场景 | 处理方式 |
|------|---------|
| 网络断开 | 提示网络不可用，引导手动输入 |
| API 超时 (>5s) | 显示加载动画 + 重试按钮 + 手动输入选项 |
| 识别失败 (无结果) | 显示"未能识别此食物" + 拍照重试 + 手动搜索 |
| 低置信度 (<70%) | 展示 Top-3 候选 + 用户可选择或手动输入 |

## 5. 数据模型 (MVP)

### 5.1 核心实体

```
User (用户)
├── id: String (UUID)
├── nickname: String
├── profile: UserProfile            ← 新增
├── calorieGoal: CalorieGoal        ← 新增
├── createdAt: DateTime
└── pets: [Pet] (1:1)

UserProfile (用户资料)              ← 新增
├── userId: String
├── gender: Enum ("male", "female")
├── birthDate: Date
├── height: Float (cm)
├── currentWeight: Float (kg)
├── activityLevel: Enum ("sedentary", "light", "moderate", "active", "very_active")
└── updatedAt: DateTime

CalorieGoal (卡路里目标)            ← 新增
├── userId: String
├── targetWeight: Float (kg)        ← 目标体重
├── goalType: Enum ("lose", "maintain", "gain")
├── dailyCalorieGoal: Float (kcal)  ← 每日卡路里目标 (BMR/TDEE 计算或手动)
├── bmr: Float (kcal)               ← 基础代谢率
├── tdee: Float (kcal)              ← 每日总消耗
├── isAutoCalculated: Bool          ← 是否自动计算
└── updatedAt: DateTime

WeightRecord (体重记录)             ← 新增
├── id: String (UUID)
├── userId: String
├── weight: Float (kg)
└── recordedAt: DateTime

Pet (宠物)
├── id: String (UUID)
├── userId: String
├── name: String (默认 "小可爱")
├── hunger: Float (0-100)           ← 含义变更: 与卡路里目标联动
├── health: Float (0-100)
├── mood: Float (0-100, derived)
├── lastFedAt: DateTime?
├── lastCalculatedAt: DateTime
└── createdAt: DateTime

FoodRecord (食物记录)
├── id: String (UUID)
├── userId: String
├── petId: String
├── foodName: String
├── calories: Float (kcal)
├── protein: Float? (g)
├── carbs: Float? (g)
├── fat: Float? (g)
├── confidence: Float? (AI 置信度)
├── imageUrl: String? (本地路径)
├── createdAt: DateTime
└── source: Enum ("ai", "manual", "favorite")
```

```
User ──1:1──► UserProfile (个人资料)

```

```
                    │

          ┌─────────────────────┐
```

### 6.3 隐私与安全

- 所有本地数据加密存储 (AES-256)
- 食物照片仅用于 AI 识别，不用于其他用途
- 用户数据本地优先存储，云端同步为可选
- 符合《个人信息保护法》要求

### 6.4 无障碍

- 支持 VoiceOver / TalkBack
- 色盲友好配色（不依赖颜色区分）
- 字体大小可调节
