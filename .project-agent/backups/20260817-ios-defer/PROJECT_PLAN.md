---

### 1.2 为什么需要新增 4 个阶段？

| 新增阶段 | 必要性分析 |
|---------|-----------|
| ➕ **P1 准备期** | PRD/TDD 已完成，但 TDD 第 10 节仍有 5 个"待决事项"（后端选型、AI API、宠物形象等）。必须在开发前敲定技术决策，否则会中途返工 |
| ➕ **P2 设计期** | TDD 明确要求建立 Design System、宠物动画状态设计、UX 用户流程。iOS/Android 双端开发**依赖设计稿**才能并行启动 |
| ➕ **P7 测试期** | PetEngine 算法需 iOS/Android **跨平台一致性验证**（TDD 6.2 节强调）；AI 识别准确率、性能指标（启动<3s）需专项测试 |
| ➕ **P9 发布期** | App Store / Google Play 审核流程需 1-3 天，且需要商店物料（截图、描述、隐私政策），不能与验收期混在一起 |

## 附录: 阶段设计方法论

### A. 为什么是这 9 个阶段？

本计划基于以下项目管理框架综合设计：

| 框架 | 应用 |
|------|------|
| **MoSCoW** (PRD 2.2) | Must Have → MVP 期；Should Have → 增量期 |
| **敏捷开发** | 2 周一个 Sprint，MVP 期 4 周 = 2 个 Sprint |
| **V 模型** | 每个开发阶段对应一个测试阶段（P3↔P7, P5↔P7） |
| **Stage-Gate** | 9 个里程碑作为质量门禁，前阶段未过不进下阶段 |
| **PRD/TDD 技术依赖** | PetEngine 一致性 → 专项测试；AI 兜底 → Demo 期验证 |

### B. 用户指定阶段 vs 新增阶段对照

```
用户指定 (5 个)                    新增 (4 个)
─────────────────                 ─────────────────
P3: MVP 开发期    ◄── 需要 ──►   P1: 准备期 (技术决策)
P4: Demo 期       ◄── 需要 ──►   P2: 设计期 (设计稿)
P5: 增量期        ◄── 需要 ──►   P7: 测试期 (质量验证)
P6: 优化期                        P9: 发布期 (商店上架)
P8: 验收期
```

**核心逻辑**: 用户的 5 个阶段覆盖了"开发→交付"的主干，新增的 4 个阶段填补了"决策→设计→测试→发布"的关键缺口，形成完整的软件生命周期。
